## Cuándo necesitas desarrollo a medida

- Tu negocio tiene un proceso manual (registros, pedidos, reportes) que consume horas cada semana.
- Necesitas que usuarios entren con su cuenta y vean o gestionen sus propios datos.
- Quieres conectar varias herramientas: formularios, bases de datos, correo, WhatsApp o servicios externos.
- Tienes una idea de producto y necesitas una primera versión funcional para probarla.

## Proyectos que he construido

Algunos ejemplos reales, con su código o demo disponibles:

- **Good Life Insurance.** Sitio profesional y registro de clientes automatizado para una aseguradora. Resultado: +50 % de clientes y +40 % de crecimiento de la empresa. [Ver el caso](/es/casos/good-life-insurance/).
- **Acortador de enlaces.** Frontend en React y backend sin servidores en AWS (Lambda, DynamoDB y API Gateway). [Ver demo](https://shortener.wickz.dev/).
- **CaseShell.** Plataforma para investigar incidentes técnicos dentro de un entorno virtual con terminal y archivos, hecha con Next.js y TypeScript. Quedó en 4.º lugar en una hackatón. [Ver demo](https://caseshell.wickz.dev).
- **NotiDev.** Plataforma de noticias diarias publicada de forma automática con n8n, construida con TanStack Start. [Ver demo](https://notidev.vercel.app).
- **Foro para Last War.** Foro para grupos de un videojuego con Vue y Supabase. [Ver demo](https://rott-guides.vercel.app/).

## Cómo trabajo

1. **Conversación inicial.** Qué problema resuelve la aplicación, quién la usa y qué es imprescindible para la primera versión.
2. **Propuesta.** Alcance, tecnologías y fases. Si algo se puede resolver de forma más simple, te lo digo.
3. **Desarrollo por partes.** Te muestro avances que puedes probar, en lugar de esperar al final para ver el resultado.
4. **Publicación.** La aplicación queda en línea, con su dominio y lista para usar.

## Arquitectura sencilla

La mayoría de los proyectos no necesita una arquitectura complicada. Prefiero soluciones que se puedan entender y mantener: menos piezas, menos dependencias y código claro. Eso hace que los cambios futuros sean más baratos, los haga yo o cualquier otro desarrollador.

Si tu proyecto es más pequeño, como presentar un producto o captar contactos, quizá te baste con una [landing page](/es/servicios/landing-pages/).
